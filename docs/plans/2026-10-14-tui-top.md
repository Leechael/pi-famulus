# Interactive TUI for `pi-famulus top`

**Date:** 2026-10-14  
**Status:** Implemented in PR #78. This is the original plan; the PR went further (see below), and `docs/cli.md` describes the shipped behavior.  
**Scope (planned):** `manager/` (`cli.rs`, `main.rs`, `stats.rs`, `inspect.rs`, `sys/unix.rs`, and new `top/` TUI module), `docs/cli.md`  
**Also changed in the PR:** `daemon.rs`, `proto.rs`, `registry.rs` and `task.rs` (persisted monitor `label`), `fmt.rs`, and the pi extension's `/tasks` views, tool rows and status glyphs (`extension/src/tui/`, `format.ts`, `monitor.ts`) with their tests, so both TUIs share one look.

---

## 1. Context and Inciting Observations

`pi-famulus top` currently prints a one-shot plain-text dump of retained task CPU grouped by agent and work kind, piped through `less -FRX` when stdout is a terminal. Running `pi-famulus top` against a real multi-project developer home (`darwin-arm64`, 36 retained sessions, 21 connected sessions, 4,560 tasks, 194 subagents) exposed four concrete usability failures:

1. **Unbounded line width (240–275 columns per line):** Every agent row repeats field labels inline (`| CPU - total, - now (sample never) | 0 task(s) | tokens unavailable in / unavailable out (cache read unavailable / write unavailable), - tok/s | wall LLM unavailable / tool unavailable / queue unavailable / unclassified unavailable`). Every row wraps across 2–4 lines even on a 120–140 column terminal.
2. **Historical noise and `unavailable` flooding:**
   - Parent sessions (`main <session>`) are not `ch_…` subagents and never have `AgentRecord` token or LLM/tool/queue wall-split telemetry, yet `top` prints `unavailable` across every token and wall field for each `main` row.
   - In `status` (`inspect.rs:sum_agent_field`), a single legacy agent record lacking `tokens_input` causes `try_fold` to return `None`, making machine-wide token totals read `unavailable`.
   - Retained records from disconnected (`gone`) sessions or pre-upgrade runs without CPU measurements sort alphabetically (`0 task(s)` next to 50-task runs), burying active and recent work under 200+ lines of dashes.
3. **Missing operational context:** Unlike `ls` and `stats`, `top` omits session CWD, agent/task status (`running`, `completed`, `failed`, `killed`), and wall-clock duration (`wall_ms`). When `cpu_ms` is unmeasured, a row shows nothing but its task count.
4. **Work-kind summary pushed off-screen:** With 213 agent lines, the `WORK KINDS` section starts at line 218 and is invisible without paging to the bottom.
5. **No live process-group CPU on macOS:** `group_cpu_ticks_by_pgid` in `manager/src/sys/unix.rs` is only implemented for Linux (`/proc`), leaving `NOW%` and running task `CPU` permanently `-` on Darwin even though `sys/unix.rs` already enumerates process-group PIDs via `libc::proc_listpgrppids`.

## 2. Confirmed Decisions

| Decision | Choice | Rationale |
|---|---|---|
| **Default main view** | **`1:Tree` (`Session → Run → Agent → Task`)**, with `Work Kinds` permanently docked in the top-right header | Matches how work is organized across concurrent `pi` sessions while keeping global work-kind slot/CPU pressure visible without scrolling |
| **Default scope** | **Connected sessions** (plus any gone session that still has running work) | Eliminates stale 24h postmortem clutter by default while matching `pi-famulus ls -a` visibility; cycling with `a` switches between `Connected`, `Active Only`, and `All Retained` |
| **TUI framework** | **`ratatui` + `crossterm`** in `manager/Cargo.toml` | Provides battle-tested double-buffered diff rendering, responsive `Layout` constraints, stateful tables/trees, and cross-platform terminal input/resize handling on Unix and Windows |
| **macOS live CPU** | **Implement Darwin live process-group CPU sampling** via `libc::proc_pidinfo(PROC_PIDTASKINFO)` | Enables live `NOW%` and cumulative running-task CPU on `darwin-arm64` / `darwin-x64` alongside Linux |

## 3. CLI Contract and Compatibility

```bash
pi-famulus top [--once] [--interval <DUR>] [--session <PREFIX>] [--cwd <DIR>] [--json]
```

### Mode selection and non-regression rules

1. **Interactive TUI mode (default on a TTY):**
   - Entered when `!json && !once && stdin_is_tty() && stdout_is_tty()`.
   - Uses alternate screen and raw mode; **never invokes the pager** (`Sub::pages()` returns `false` for interactive `Top`).
   - Polls daemon/disk state on a background ticker (default `--interval 1s`, adjustable in-app via `+`/`-` across `500ms`, `1s`, `2s`, `5s`).
2. **One-shot snapshot mode (`--once` or non-TTY stdout):**
   - Triggered when `--once` is passed or when stdout/stdin is not a terminal (e.g., `pi-famulus top | head`, scripts, and existing black-box test harnesses like `c12` and `c13`).
   - Preserves the existing plain-text snapshot output so existing tests and pipes continue to pass unchanged.
3. **Machine-readable mode (`--json`):**
   - Prints `TopReport` JSON and exits 0 immediately. Wire-compatible with existing `c12_top_reports_agent_cpu_kind_cpu_and_tokens` and `c13_top_reports_live_process_group_cpu`.
4. **Daemon lifecycle invariant:**
   - Like `status`, `sessions`, `show`, and `stats`, `pi-famulus top` **never spawns the daemon** (`Live::IfRunning`) when opening or refreshing.
   - If the daemon is offline, the TUI header displays `[OFFLINE · DISK SNAPSHOT]` and remains fully interactive over retained disk records and transcripts.
   - Only an explicit user action to stop a running task (`x` / `Ctrl+X` confirmed on a live `sh_` or `mon_` task) connects to the running daemon and sends `RequestKind::Stop { task_id, reason: Some("tui") }`.

## 5. View Semantics and Smart Roll-up

### 5.1 View `[1] Tree` (Default)

Organizes work into up to four levels with roll-up metrics (`tasks`, `wall_ms`, `cpu_ms`, `cpu_now_percent`, `tokens_input/output`):

1. **`Session` node (`01a13622 · ~/workshop/phala/teehouse`):**
   - Shows session state (`connected` / `gone`), `pi_pid`, CWD (`~`-shortened), total tasks/agents, rolled-up CPU, and live `NOW%`.
2. **`main <session>` node (under `Session`):**
   - Groups shells and monitors spawned directly by the parent session (`origin.child_id == None`).
3. **`Run` node (`run_6f50e7cc`, under `Session`):**
   - Groups subagent children belonging to the same `run_id` (or direct `ch_…` nodes under `Session` if `run_id` is absent).
4. **`Agent` node (`ch_b76c494d P5-contracts`, under `Run`):**
   - Shows subagent name, agent definition, model, status, token usage, `output tok/s`, wall split, and child task count.
5. **`Task` leaf node (`sh_…` / `mon_…`, under `main` or `Agent`):**
   - Individual shell or monitor execution with its classified `work_kind`, duration, CPU, `NOW%`, exit code/signal, and command head.

#### Smart Roll-up (Default Expansion Policy)
- **Live path auto-expansion:** Any branch containing a `running` or `pending` task or subagent is expanded all the way to the running leaf node by default.
- **Finished leaf folding:** Completed/failed/killed shell tasks under `main <session>` or `ch_…` are **collapsed into their parent node by default** (preventing a session with 1,500 finished `rg`/`git` calls from flooding the screen). Users expand any node on demand with `→` / `l` and collapse with `←` / `h`, or toggle global expand/collapse with `z`.

### 5.2 View `[2] Agents`

A flat, sortable leaderboard of all subagents (`ch_…`) and parent sessions (`main <session>`) within the active scope:
- Replaces the legacy 275-column text lines with aligned columns and `-` for N/A fields (`main <session>` never prints `unavailable` for agent-only fields).
- **Improved multi-key default sort:** `running` first → `cpu_now_percent` ↓ → `cpu_ms` ↓ → `wall_ms` (agent or task wall duration) ↓ → `tasks` count ↓ → `started_at` ↓. Unmeasured agents with substantial wall time or task counts rank above idle 0-task agents.

### 5.3 View `[3] Tasks`

A flat, sortable table of `Row` items (`sh_`, `mon_`, `ch_`), equivalent to an interactive `pi-famulus ls` with live sorting (`CPU`, `NOW%`, `DUR`, `TIME`) and instant substring filtering (`/`).

### 5.4 View `[4] Events`

A live-tailing table of merged `events.jsonl` across sessions (`task.start/exit`, `agent.start/settle/overrun`, `wake.emit/deliver/inject` with `lag_ms`, `capacity.changed`).
- Pressing `e` on any selected node in Views `1..3` jumps to `4:Events` pre-filtered to that `session_id`, `run_id`, `child_id`, or `task_id`.

### 5.5 Detail Inspection (`v` Split Pane & `Enter` Full-Screen Modal)

- **Bottom Split Preview (`v`):** Toggles a bottom pane showing live tail lines of the selected item without leaving the table.
- **Full-Screen Detail (`Enter` to open, `Esc` to close):**
  - **For `sh_` / `mon_`:** Tabs `1:Output` (`.output` tail/follow), `2:Stderr` (`.stderr` tail/follow), `3:Info & Wake` (full metadata, command, CPU/RSS breakdown, wake emit → deliver → inject timeline).
  - **For `ch_`:** Tabs `1:Transcript` (rendered `<ch>.jsonl` conversation, `F` to toggle `--full` preamble), `2:Result` (`result_tail`), `3:Info & Shells` (prompt, token/wall breakdown, spawned shells).
  - Supports `↑`/`↓`/`PgUp`/`PgDn`/`Home`/`End` scrolling and `f` to toggle live follow-tail.

| Key | Action |

| `↑` / `↓` or `k` / `j` | Move selection up / down (selection is anchored by item ID across refreshes) |
| `←` / `→` or `h` / `l` | Fold / unfold node in `1:Tree` (or jump to parent / first child) |
| `z` | Reset / toggle expand-all in `1:Tree` |
| `PgUp` / `PgDn`, `g` / `G` (`Home` / `End`) | Page up / down, jump to top / bottom |
| `a` | Cycle Scope: `Connected (default)` → `Active Only` → `All Retained (24h)` |
| `s` / `S` or `<` / `>`, `I` | Cycle sort column (`CPU`, `NOW%`, `WALL`, `TASKS`, `TOKENS`, `TIME`); `I` inverts order |
| `/` | Open inline filter bar (matches ID, name, command, CWD, work kind, status); `Esc` clears |
| `v` | Toggle bottom master-detail preview pane |
| `Enter` | Open full-screen detail view for selected item (`Esc` returns to previous view & cursor) |
| `e` | Jump to `4:Events` filtered by the selected item's ID |
| `x` / `Ctrl+X` / `F9` | Stop selected running `sh_`/`mon_` task (inline confirmation `Stop <id>? [y/Enter] [n/Esc]`; explains `/tasks` if an agent `ch_` is selected) |
| `p` / `Space` | Pause / resume UI refresh (`[PAUSED]`) |
| `+` / `-` | Increase / decrease refresh interval (`500ms` ↔ `1s` ↔ `2s` ↔ `5s`) |
| `?` | Toggle help overlay |
| `q` / `Ctrl+C` | Quit `pi-famulus top` |

## 7. Architecture and Implementation Plan

### 7.1 Module Layout (`manager/src/`)

```text
manager/src/
├── cli.rs          # Add --once, --interval, --session, --cwd to Sub::Top; update Sub::pages()
├── main.rs         # Route Sub::Top to top::run() or stats::cmd_top()
├── stats.rs        # Keep TopReport (--json / --once) + partial token aggregation helper
├── sys/unix.rs     # Add #[cfg(target_os = "macos")] group_cpu_ticks_by_pgid & clock_ticks_per_second
└── top/
    ├── mod.rs      # Entry point, TTY detection, terminal guard (raw mode + alternate screen + panic hook)
    ├── model.rs    # Pure state machine: TopState, Scope, Tab, SortKey, TreeNode, filter/sort/fold logic
    ├── collector.rs# Background async poller (Snapshot + incremental file tail for active preview/detail)
    └── ui.rs       # Ratatui rendering: responsive header, tree/agent/task/event tables, detail modal, help
```

### 7.2 Unidirectional Data Flow (Collector ↔ State ↔ Renderer)

- **No I/O on the render path:** `ui::draw(frame, &mut state)` is a pure function of `TopState` and terminal `Rect`.
- **Collector task:** Runs on a `tokio::select!` loop driven by `interval` ticks and on-demand refresh triggers (e.g., after stopping a task or changing detail target). Calls `inspect::snapshot(&home, Live::IfRunning)` and reads tail bytes (capped at 64 KiB via `task::read_file_range`) only for the currently inspected item.
- **Terminal restoration:** A RAII `TerminalGuard` plus a custom panic hook ensures raw mode and alternate screen are always restored on normal exit, error return, or panic.

### 7.3 macOS Live Process-Group CPU Sampling (`manager/src/sys/unix.rs`) — implemented

- On `#[cfg(target_os = "macos")]`, implement `group_cpu_ticks_by_pgid(pgids: &[u32]) -> io::Result<HashMap<u32, (u64, u64)>>`:
  1. Call existing `group_members(pgid)` (`libc::proc_listpgrppids`) for each requested process group.
  2. For each member `pid`, call `libc::proc_pidinfo(pid as i32, libc::PROC_PIDTASKINFO, 0, &mut task_info, size)`.
  3. Convert `pti_total_user` and `pti_total_system` from Mach absolute time units to nanoseconds via `mach_timebase_info`, then to milliseconds (`clock_ticks_per_second() -> Some(1_000)` on macOS).
  4. Sum `(user_ms, sys_ms)` across all live members of the process group.
- In `daemon.rs`, `LiveCpuTracker` already handles high-water marks when short-lived children exit between polls and computes `live_cpu_percent` across intervals.
- Reduce `LIVE_CPU_POLL` from `5s` to `2s` so `NOW%` updates briskly in both `top` and `ls`.

### 7.4 Token Aggregation Fix

- Keep `status --json` strict `agent_tokens` field compatible if required by existing contract tests, or add partial-aware summation in the TUI header (`tokens_measured_agents / total_agents`) so a single legacy record with `tokens_input: null` does not blank out token totals for sessions that do report usage.

## 8. Testing Strategy

1. **Unit tests (`manager/src/top/model.rs`):**
   - Tree construction and roll-up arithmetic (`Session → Run → Agent → Task`), verifying that live branches auto-expand while finished shell leaves fold under their parent.
   - Scope filtering (`Connected`, `Active Only`, `All Retained`), substring search (`/`), and multi-key sorting.
   - Cursor stability across snapshot refreshes when rows reorder or disappear.
   - Responsive column selection across `80`, `120`, and `160` column widths using `ratatui::backend::TestBackend` (verifying zero line wraps and no panics down to tiny `40x10` terminals).
2. **macOS & Linux live CPU tests (`manager/src/sys/unix.rs` & `manager/tests/observability.rs`):**
   - Unit test in `sys/unix.rs` verifying `group_cpu_ticks_by_pgid` reports growing CPU milliseconds for a busy child process group on both Linux and macOS.
   - Enable `c13_top_reports_live_process_group_cpu` on `#[cfg(any(target_os = "linux", target_os = "macos"))]`. (done)
3. **CLI compatibility tests (`manager/tests/observability.rs` & `cli.rs`):**
   - Verify `pi-famulus top --json` and non-TTY `pi-famulus top` / `pi-famulus top --once` pass all existing assertions without starting the daemon.
